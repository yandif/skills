# 实现要点

这些是基于官方接口约束的工程策略；按用户任务采用，不强迫简单程序使用完整架构。精确接口仍以 pages/ 中方法正文为准。

## 海龟

### 动作、路径和燃料

统一移动函数可返回 `true` 或 `false, reason`，并仅在成功后更新状态。每次失败区分没燃料、方块、生物、保护区域、工具缺失或未知原因；用 inspect 和燃料状态补充信息，避免依赖会变动的错误文本。对可重试障碍设置次数/时间上限与 sleep，让用户能中止。只有任务允许才 dig/attack。

相对坐标可约定初始前方为 +z、右方为 +x、上方为 +y，并用 0–3 朝向表示旋转；这与 Minecraft 的真实东南西北不同，必须说明。GPS 绝对坐标的 x 东、y 上、z 南；朝向需要用户输入或可安全移动的方向校准。不要声称原版 turtle 有后方 inspect/dig/place；要查询后方需转向，并检查转向成功与恢复结果。

按路线估算移动燃料和返航裕量，转向不耗移动燃料。先判定 `getFuelLevel()` 是数字还是 `"unlimited"`。`refuel(0)` 可判断选中物品是否能用作燃料；检查返回值，保留原选中格，避免消耗有用途的燃料材料。复杂任务报告已完成距离/区域及停止原因，不以成功提示覆盖失败。

挖掘连续沙砾/沙子需要有界处理落块；处理背包满、不可挖掘方块、容器、流体和实体。不要从 `detect()==false` 推断没有实体或流体。农场利用 inspect 的方块名称、state 和实际作物成熟状态；各种作物/树形/模组规则需查证，不硬套统一 age。

### 背包、合成和储物

16 格槽位为 1–16，选中格影响 place/drop/refuel/equip 等。保留燃料、种子、工具与建筑材料，不一键丢弃全部。`getItemDetail` 空槽返回 nil；详细字段与 tags 取决于参数及版本。

Crafting turtle 的网格是 4×4 背包里的一个合法 3×3 区域，例如左上区域 1,2,3 / 5,6,7 / 9,10,11，其他格须符合官方合成约束；检查工作台升级和输出空间，`craft(0)` 只测试配方。配方与版本/数据包有关，不能保证任意模组配方可以 turtle.craft。

`turtle_storage` 从 1.121.0 加入。其 push/pull 操作是储物升级与海龟内部背包之间传输，参数没有 generic inventory 的目标外设名，不混用二者。旧版必须检测能力或提供其他方案。

### 中断与恢复

持久状态包含任务配置/版本、进度、位置、朝向与动作阶段。写入临时文件后关闭并保留上一份有效检查点，替换文件不应宣称为跨崩溃事务。游戏动作和磁盘记录之间可能发生中断；重启时对 pending 动作利用 GPS/inspect/物品差异重新确认，无法确定就停在可解释状态或请求校准，而非盲目继续挖掘。

远程 UI/控制与海龟移动分离为消息队列或单一执行者，避免并发任务同时改变朝向、选中格或世界。

## 电脑、外设和仓储

`peripheral.find` 可返回多个对象。多设备时用实际名字选取和 `peripheral.hasType` 检测复合类型；不要只用 `getType(name)=="inventory"` 判断所有能力。wired modem 网络须实际连接并启用外设暴露；generic inventory 的 pushItems/pullItems 使用外设网络名，不能凭方块名猜目标名。

`inventory.list()` 是按槽位索引的稀疏表，遍历用 pairs；槽位数量用 size，不用 `#list` 或 ipairs 推断。返回基础 name/count/nbt；nbt 可用于区分带不同数据的物品，详细字段通过 getItemDetail 查证。push/pull 返回实际转移数，0 是正常无进展情况，不能算完成或无间隔重试。目标满、源变化、外设 detach 时重新发现设备并报告状态。

流体接口以官方毫桶/数量定义为准，能量单位取决于对应模组；传输数量与容量不能从另一个模组移植。第三方机械/扫描器的接口不由 tweaked.cc 保证。

`fs.open` 可能返回 nil 与错误信息；检查后再读写并关闭。反序列化可能返回 nil；验证保存数据的类型、范围与 schemaVersion，不把不可信数据当作代码 load 执行。settings 更改需要 save 才持久化，失败必须报告。

启动顺序见 reference/startup：ROM autorun 在先，允许磁盘启动时首个匹配磁盘可能覆盖本机启动；之后是根目录 startup/startup.lua 与 startup/ 目录。目录按字典序依次运行，不能依靠多个长运行文件自动并发。启动包装保持用户可中止，避免无限崩溃重启；命令行参数按实际 shell.run 签名传递。

## 事件、并发和 UI

事件元组从事件名开始。用 table.pack/table.unpack（必要时指定 n）保留 nil；modem 的 distance 在跨维度时可为 nil，不能直接 `%f` 格式化。定时器对比返回的 timer ID，超时别误认其他 timer。

多事件程序用 `os.pullEvent()` 后分发，不在同一个消费者里反复调用只拉单类事件的阻塞函数。`os.pullEvent("timer")`、sleep、rednet.receive、websocket.receive 等可能使该协程忽略其他事件。parallel 为每个任务提供副本并在 yield 时调度；CPU 紧循环不会自动协作。传函数对象，不能把函数调用结果传给 waitForAny/All。waitForAny 任一结束后不再运行剩余任务；错误传播，清理应由外层承担。waitForAll 的 spawn 参数是 1.120.0 新功能，不默认用于旧版本。

保持默认 Ctrl+T 行为；只有确实需要接管退出清理才用 pullEventRaw，并显式处理 terminate。用 xpcall/pcall 后需要识别并继续传播用户终止，而不是吞掉 Terminated 进入重试。退出时视任务恢复 term.redirect、关闭打开的句柄/通道，停止音频并把红石置于用户约定的状态；不要假定低电平适合所有机器。

终端坐标从 1 开始，文本写入不保证自动换行；blit 的文本、前景和背景字符串长度必须相同。查询实际尺寸，处理 term_resize/monitor_resize。触屏坐标绑定到事件携带的监视器名，不能把另一块屏幕的触摸当成本屏输入。高级能力需检测，普通电脑/监视器采用合适降级。默认英文界面并非 Lua 注释不能写中文。

## 网络和音频

rednet 先 open 实际 modem 外设名；lookup/host 的 protocol 用于应用分流，不提供身份验证、加密或可靠投递。按需求设计协议版本、请求 ID、允许命令、参数范围、超时重试和去重；重复的非幂等动作必须避免再次执行。不要远程 load 收到的字符串。来自可信网络之外的敏感控制需要真正认证；简单电脑 ID 白名单只防误路由，不防伪造。

直接 modem 通信区分发送 channel 和 replyChannel，监听前 open channel；协议与 rednet 不混用。检查无线/有线/Ender modem、维度、距离、GPS 主机加载与服务器配置。GPS 服务需要多个位置不同的主机，采用官方四主机空间布局；不从一次位置读取推断朝向。

HTTP 受服务器启用/地址规则/并发和大小限制影响，局域网默认限制见 local_ips。get/post/request/WebSocket 的同步、异步及多返回值不同；错误 HTTP 响应可能仍有可读句柄，成功和失败路径都应关闭资源。不要自行修改服务器网络规则来掩盖失败。

DFPWM 用一个持续 decoder 处理连续分块，不能每块重建状态。playAudio 接收 -128..127 PCM 样本、48 kHz，单次最多 128×1024 样本。返回 false 表示缓冲不能接收，等待属于目标 speaker 的 speaker_audio_empty 后重试；不把 false 当成永久失败，也不忙循环。实际支持按 speaker 和 dfpwm 文档版本判断。

## 验证和交付

对算法重点验证路径终点/朝向、材料与燃料预算、稀疏库存、部分传输、超时、取消及失败状态。模拟 turtle 时主动注入移动失败、满背包、缺燃料；成功路径测试不足以证明导航正确。需要恢复时模拟 pending 动作前后断电。测试复杂度与请求成比例，简单显示程序无需搭建完整框架。

说明哪些检查已真正执行，以及哪些只能由用户游戏确认。交付 CraftOS 文件名、运行命令、起点/朝向、外设摆放、升级与配置；不把桌面 filesystem 路径当作游戏 fs 路径，不假定 Minecraft 世界存档目录在当前项目。
