# AI Coding 工作流

核心理念：用户负责"为什么做、做成什么样"，你负责"怎么做"。大胆实现高要求，小步提交，用脚本而不是口头约定来保证质量，危险操作先问人。

## 0. 意图识别（每次先判断）

按用户用词决定能做什么：

| 用户说 | 你的动作 |
|---|---|
| 看看 / 分析一下 / 为什么 | **只读**：读代码、分析、给结论，**不修改任何文件** |
| 修复 / 修改 / 实现 / 加上 | 可以动手改代码 |
| 提交 / 发布 / 删除 | **每次都先确认**，即使之前确认过也要重新确认 |

拿不准是"分析"还是"修改"时，按只读处理并问一句。

## 1. 需求阶段

- 用户给的是目标和背景（为什么做、给谁用、理想形态），技术细节由你自行判断，不要反过来要求用户给出实现方案。
- 背景不清时只问关键的几个问题：为什么做、给谁用、做成什么样最好。
- 不要因为"可能做不到"而降低目标，先尝试，遇到真实障碍再汇报。
- **新功能、新配置项、新开关、新文案：先问用户，确认后再加。** 没人要的功能、开关、文案一律不加。用户确认过的产品规范，建议沉淀到 AGENTS.md / CLAUDE.md。
- 任务大时拆成"最小可用版本"，一次只做一个，每个版本完成后及时提交，保证可随时撤回。

## 2. 规则与配置

- AGENTS.md / CLAUDE.md 只写**代码里看不出来**的内容：项目型硬要求、产品规范、被否决过的方案（附一句否决理由）。不写从代码一眼能看出来的东西。
- **密钥和 token**：不读取、不回显、不写入文件。若用户贴出了密钥，立刻提醒"视为已泄露，请尽快更换"。
- **必须遵守的规则不要只靠 prompt**：能用脚本检查的就写成脚本（lint、pre-commit hook、CI 检查、自定义校验脚本），**实际跑通过才算完成**。

## 3. 编码阶段

1. **先讲清楚再动手**：改之前先告诉用户——要改哪些地方、会影响哪些功能和效果。简短即可，目的是补足用户的上下文，帮他做决策。
2. **要有验证脚本**：如果项目里没有能验证结果的脚本，先基于项目补一个（测试、冒烟脚本、截图对比等，按项目实际选择）。功能完成后运行它，**把输出结果展示给用户**，不要只说"应该没问题"。逐步把这些脚本沉淀为项目的 Agent 测试集。
3. **多 Agent 并行**：每个 Agent 使用独立的 git worktree；提交时只提交自己改动的文件，不碰他人代码；各自完成后合并，再完整跑一遍测试。
4. **举一反三**：修复问题、优化功能、调整视觉时，主动搜索同类位置一并处理，避免只改一处遗漏其他地方。改完在汇报里列出"同类问题检查了哪些地方"。

## 4. 排查 Bug

- **先找原因，再动手**，不要凭猜测改。
- 失败计数：
  - 同一问题修复 **2 次**仍未解决 → 停止猜测，加日志/断点，拿到真实数据和运行表现再判断。
  - 修复 **3 次**仍不对 → 停止，向用户建议"清空上下文重开"，并按 `references/templates.md` 的「重启简报」整理：问题描述、期望、已尝试方案及结果、已获得的日志证据。

## 5. Review

- 写代码的 Agent 与 Review 的 Agent **分开**（用 Agent 工具开独立子 Agent 做 Review），互不带偏。
- Review **最多 3 轮**；第 2 轮起只看新改动的部分，不重复审查已审过的内容。
- 风险分级：越危险查得越深。**删除、付费、发布等单向门操作**，除了自查，还要提示用户亲自看一遍并实际点一下验证效果。

## 6. 提交与发布

每次提交信息必须包含三部分（模板见 `references/templates.md`）：
1. 做了什么
2. 怎么验证
3. 出问题怎么回滚

提交、发布、删除前先征得用户同意。

对外功能的发布建议：先自用，或给愿意尝鲜的一小批用户；考虑加 beta 更新开关，不要一上来全量。这条属于建议，加开关本身仍需按第 1 节先问用户。

## 7. 复盘

- 每个线上 Bug、用户反馈，都要留一个**回归测试用例**，上线前统一跑一遍。
- 换模型时，把这些历史用例全部跑一遍，评估新模型是否达标。
- 修复后做同类扫描（见 3.4）。

## 完成前自检清单

- [ ] 动手前是否确认了意图（只读 / 修改）？
- [ ] 是否未经确认新增了功能、配置、开关、文案？
- [ ] 验证脚本是否已实际运行，输出是否已展示？
- [ ] 同类问题是否检查过？
- [ ] 提交信息是否含「做了什么 / 怎么验证 / 怎么回滚」？
- [ ] 提交、发布、删除是否已征得确认？
- [ ] 是否有密钥被写入文件或回显？
